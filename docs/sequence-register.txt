  Supabase Auth: xử lý signUp; xem Authentication > Users.
  PostgREST: API truy vấn bảng khi frontend lấy role.
  Xem lời gọi: frontend/src/features/auth/authService.js.
  Quan sát request trong trình duyệt: Network > auth/v1 hoặc rest/v1.
  Đây là dịch vụ Supabase quản lý, không phải file server trong repo.

User -> FR : Nhập email, mật khẩu; chọn Đăng ký
FR -> FR : Loại bỏ khoảng trắng; kiểm tra dữ liệu rỗng
note right of FR
  Nếu email hoặc mật khẩu rỗng: báo lỗi và dừng,
  không gửi yêu cầu đến Supabase.
  Luồng tiếp theo giả định đã nhập đủ thông tin.
end note

FR -> BE : signUp({ email, password })
BE -> BE : Kiểm tra yêu cầu theo cấu hình Auth
alt Yêu cầu bị Auth từ chối
  BE -> BE : Chuẩn bị kết quả lỗi
else Yêu cầu được xử lý
  BE -> DB : Kiểm tra email; tạo auth.users nếu cần
  opt Có INSERT user mới và trigger đã được triển khai
    DB -> DB : AFTER INSERT gọi handle_new_loki_user()
    DB -> DB : Tạo/cập nhật public.app_users, role mặc định là user
  end
  DB --> BE : Kết quả xử lý danh tính
end

BE --> FR : result.error, result.data.session, result.data.user
FR -> FR : Kiểm tra error, session và user theo thứ tự
note right of FR
  error có giá trị: hiển thị lỗi; nếu Auth trả lỗi email trùng,
  thông báo email đã đăng ký và đề nghị đăng nhập.
  Không lỗi, session rỗng: giữ form, đề nghị kiểm tra email
  hoặc đăng nhập nếu đã có tài khoản.
  Có session, user rỗng: lưu lỗi không nhận được tài khoản.
  Có session và user: lấy role, cập nhật trạng thái đăng nhập.
  Có thể chuyển giữa Login và Sign up ngay trong form.
end note
FR --> User : Cập nhật giao diện theo kết quả

  Không có session không chứng minh user mới đã được tạo.
  Auth có thể không trả lỗi email trùng do cấu hình bảo mật.
  Trigger / app_users: backend/supabase/admin_roles.sql.
end note
